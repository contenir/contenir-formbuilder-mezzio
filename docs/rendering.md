# Rendering

Rendering needs the request: the CSRF token and the error stash live in its
session, and `?submit=<slug>` marks a successful submission. So instead of
view helpers, the page's handler asks for the form and passes the result to
its template.

## `FormBlockRenderer`

```php
$html = $formBlockRenderer->render($request, 'contact'); // '' for an unknown slug
```

Renders the `formbuilder::form` template (or `formbuilder.template`) with the
`PresentedForm` as `form`. The bundled template:

- wraps the block in `<div class="formbuilder" id="formbuilder-<slug>">`;
- after a successful submission, shows `formbuilder__success` with
  `settings.success.title` (default "Thank you") and `settings.success.message`,
  both escaped;
- otherwise shows the form, preceded by a `formbuilder__notice` when the last
  submission's CSRF token was rejected (an expired session, typically).

The template is plain PHP, so the laminas-view and Plates renderers both
render it; with another engine, set `formbuilder.template` to your own
template.

## `FormPresenter`

```php
$presented = $formPresenter->present($request, 'contact'); // ?PresentedForm
```

1. Loads the definition through `FormLoaderInterface` (null when there is no
   form with the slug).
2. Builds the form with the core builder and the session's CSRF token.
3. Sets its `action` to the submit route, generated by `RouterInterface` from
   `formbuilder.submit_route.name`.
4. Consumes the [error stash](submitting.md#the-error-stash) and, when there is
   an entry, hydrates the form with `setData()` and `setMessages()`.
5. Renders it with the core `Contenir\FormBuilder\Render\FormMarkup` and adds a
   hidden `_anchor` input (`formbuilder-<slug>`) so the visitor returns to the
   form after submitting.

`PresentedForm` exposes:

| Property | |
| --- | --- |
| `definition` | The `FormDefinition` |
| `form` | The built, hydrated Laminas form |
| `html` | The rendered form |
| `anchor` | `formbuilder-<slug>`, characters outside `[A-Za-z0-9_-]` replaced by `-` |
| `submitted` | Whether the query's `submit` is this form's slug |
| `successTitle`, `successMessage` | `settings.success.title` and `.message`, or null |
| `errors` | The stashed validation messages, `_csrf` included when the token was rejected |

For your own markup, render `form` and `definition` yourself, for example with
`new FormMarkup()` and your escaper:

```php
$markup = new Contenir\FormBuilder\Render\FormMarkup();
$markup->setEscaper($escaper);
echo $markup->render($presented->definition, $presented->form);
```

The form keeps the session's token, whatever the stashed values say, so a
re-rendered form always posts a valid one.

A request without a mezzio-session throws `MissingSessionException`.
